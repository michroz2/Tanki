## 1. Обзор проекта

| Компонент | Содержимое |
|-----------|------------|
| **Прошивка** | ESP32 (LOLIN32 Lite), PlatformIO, Arduino framework |
| **Исходники** | 7 модулей C++ (~700 строк) в `Firmware/Tanki/src/` |
| **Документация** | Дорожная карта, схемы питания, pinout |
| **Тесты** | Отсутствуют (только шаблон PlatformIO) |
| **README** | Отсутствует |

Проект представляет собой прошивку радиоуправляемого танка масштаба 1:16. Реализованы: приём сигнала i-BUS, ШИМ-управление гусеницами (BTS7960) и башней (DRV8833), I2S-звук (MAX98357A), конечный автомат безопасности.

### Структура исходников

```
Firmware/Tanki/src/
├── main.cpp           — FSM, failsafe, оркестрация
├── ibus_parser.h/cpp  — парсинг FlySky i-BUS
├── mixer.h/cpp        — дифференциальный микшер
├── motor_control.h/cpp — ШИМ гусениц (LEDC)
├── turret_control.h/cpp — ШИМ башни (LEDC)
└── audio_system.h/cpp — I2S + FreeRTOS на Core 0
```

## 2. Архитектура прошивки

```
main.cpp (FSM, failsafe, оркестрация)
    ├── ibus_parser    — UART Serial2, парсинг FlySky i-BUS
    ├── mixer          — дифференциальный микшер CH1/CH2
    ├── motor_control  — LEDC ШИМ, 4 канала, гусеницы
    ├── turret_control — LEDC ШИМ, 2 канала, башня
    └── audio_system   — I2S + FreeRTOS task на Core 0
```

### Сильные стороны

- Модульная структура: каждый функциональный блок в отдельных `.h`/`.cpp`
- Разделение нагрузки: Core 0 (аудио) / Core 1 (управление)
- FSM с явными состояниями: `DISARMED → STARTING → RUNNING`, аварийный `WARNING`
- Безопасный старт: SWA + центрированные стики
- Аппаратный failsafe: таймаут 200 ms + CH3 ≤ 1000
- Ограничение сирены ровно 15 секунд

### Конечный автомат (FSM)

| Состояние | Поведение |
|-----------|-----------|
| `STATE_DISARMED` | Моторы 0, звук MUTE. Переход в STARTING при SWA + центр стиков |
| `STATE_WARNING` | Моторы 0, сирена до 15 с, затем MUTE |
| `STATE_STARTING` | Моторы 0, звук стартера 3 с, блокировка ввода |
| `STATE_RUNNING` | Полное управление: микшер, башня, динамический звук двигателя |

## 4. Критические и высокоприоритетные проблемы

### 4.1. Окно безопасности при потере связи (200 ms)

**Файл:** `Firmware/Tanki/src/main.cpp`

```cpp
bool rxTimeout   = (millis() - lastPacketTime > SIGNAL_TIMEOUT_MS);
bool ch3Failsafe = (ch3 <= 1000);
bool signalLost  = rxTimeout || ch3Failsafe;
```

**Проблема:** если приёмник не переводит CH3 в failsafe-позицию мгновенно, до 200 ms танк продолжает ехать с **последними** значениями каналов в `STATE_RUNNING`.

**Рекомендация:** уменьшить `SIGNAL_TIMEOUT_MS` до 50–100 ms или останавливать моторы при отсутствии валидного пакета в течение N циклов `loop()`.

**Severity:** 🔴 High

---

### 4.2. WAV-файлы отсутствуют в репозитории

**Файл:** `Firmware/Tanki/src/audio_system.cpp`

Прошивка ожидает `/start.wav` и `/idle.wav` в файловой системе LittleFS, но в репозитории нет папки `data/` и нет `.wav`-файлов. При отсутствии файлов — тишина и сообщения `AUDIO ERR` в Serial.

**Рекомендация:**

- Добавить `Firmware/Tanki/data/start.wav` и `idle.wav`
- Добавить инструкцию: `pio run -t uploadfs`
- Задокументировать требования к формату (PCM 16-bit, mono, 16 kHz)

**Severity:** 🔴 High

---

### 4.3. Сервопривод орудия не реализован

**Файл:** `Firmware/Tanki/src/main.cpp`

```cpp
pinMode(PIN_SERVO, OUTPUT);
digitalWrite(PIN_SERVO, LOW);
```

Шаг 5 дорожной карты (библиотека ESP32Servo, управление стволом, имитация отдачи) не выполнен.

**Severity:** 🟡 Medium (функциональный пробел, не блокер безопасности)

---

### 4.4. Нет аппаратного watchdog (WDT)

При зависании `loop()` моторы могут остаться в последнем состоянии. FreeRTOS WDT для audio task не настроен явно.

**Рекомендация:** включить `esp_task_wdt` или hardware WDT с периодическим сбросом в `loop()`.

**Severity:** 🟡 Medium

## 5. Средний приоритет

### 5.1. Дублирование констант deadband

Константы `DEADBAND_MIN`, `DEADBAND_MAX`, `CENTER_VAL` определены и в `main.cpp`, и в `mixer.cpp`. При изменении в одном файле легко получить рассогласование.

**Рекомендация:** вынести в общий `config.h`.

---

### 5.2. Глобальный массив `channels[]` без синхронизации

`ibus_parser` пишет в массив, `main.cpp` читает. Audio task напрямую не читает — для `int` на ESP32 практически приемлемо, но формально это data race.

**Рекомендация:** пометить `volatile` или делать snapshot каналов в начале `loop()`.

---

### 5.3. `readIBus()` — потенциальная блокировка

Цикл `while (Serial2.available())` может задержать `loop()` при большом буфере. Для i-BUS (32 байта/пакет) обычно не критично, но стоит ограничить число итераций за один вызов.

---

### 5.4. Объявление переменной в `case` без фигурных скобок

**Файл:** `Firmware/Tanki/src/main.cpp`, `case STATE_RUNNING`

```cpp
case STATE_RUNNING:
  updateMixer(throttle, steering);
  int turretSpeed = map(turretRaw, 1000, 2000, -255, 255);
  setTurretSpeed(turretSpeed);
  break;
```

Сейчас компилируется (последний case), но при добавлении новых case возникнет ошибка компиляции. Обернуть тело case в `{ }`.

---

### 5.5. Deadband башни дублирует логику микшера

Обработка deadband для башни выполняется в `main.cpp`, для газа/руля — в `mixer.cpp`. Лучше общая функция `applyDeadband(value)`.

---

### 5.6. `initAudio()` при ошибке LittleFS

При сбое монтирования FS функция выходит без создания audio task — управление продолжается, звук молча отсутствует. Стоит добавить явный флаг `audioReady` и логировать состояние при старте.

## 8. Аудиоподсистема

### Плюсы

- I2S на Core 0, DMA, не блокирует управление
- Регулировка громкости через CH5 (VRA)
- Динамическая частота двигателя по газу (16–26 kHz sample rate)
- Режимы: `MUTE`, `SIREN`, `START`, `ENGINE`
- Программная сирена (600 Hz / 400 Hz)

### Минусы

- Нет файла выстрела (шаг 7 дорожной карты)
- Жёстко зашит `seek(44)` — только WAV PCM с 44-байтовым заголовком
- `currentVolume` — `volatile float`, без atomic (на практике обычно OK)
- Нет плавного crossfade между режимами

### Аппаратная конфигурация I2S

| Параметр | Значение |
|----------|----------|
| BCLK | GPIO 26 |
| LRC (WS) | GPIO 25 |
| DIN | GPIO 27 |
| Sample rate | 16000 Hz (базовый), до 26000 Hz |
| Формат | 16-bit, stereo (mono дублируется) |

## 9. i-BUS парсер

### Плюсы

- Синхронизация по маркерам `0x20` / `0x40`
- Проверка контрольной суммы (FlySky spec)
- Неблокирующее чтение из UART Serial2 @ 115200
- Инициализация каналов нейтралью 1500 µs

### Минусы

- Нет валидации диапазона каналов (1000–2000)
- При сбое синхронизации — только сброс `byteIdx`, без статистики потерь
- Нет API «свежести» данных (age of last valid packet)

### Назначение каналов (по `main.cpp`)

| Индекс | Канал пульта | Назначение |
|--------|-------------|------------|
| `channels[0]` | CH1 | Поворот (steering) |
| `channels[1]` | CH2 | Газ (throttle) |
| `channels[2]` | CH3 | Failsafe-триггер (≤ 1000) |
| `channels[3]` | CH4 | Башня |
| `channels[4]` | CH5 | Громкость (VRA) |
| `channels[6]` | CH7 | SWA — предохранитель |
